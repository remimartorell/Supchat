"Voici un aperçu global de la solution SupChat telle qu’elle est organisée et codée :

1. Architecture générale
Conteneurisation via docker-compose.yml à la racine, qui lance trois services :

backend (Node/Express, MongoDB)

frontend (React web, servi par Nginx)

mongodb

Trois clients :

Web : un single-page app React (CRA), avec routage React-Router, thème dynamique (CSS variables), Axios pour l’API.

Mobile : un Expo/React Native app, avec navigation Stack/Drawer/BottomTabs, écrans et composants très proches du web pour garder une UX cohérente.

(Éventuellement) un client OAuth2 envisagé, mais pas encore intégré.

2. Backend (supchat-backend)
Modèles Mongoose

User, Workspace, Channel, Message, DirectMessage, Notification

Schémas supportant : réactions (emoji), pièces-jointes, read-receipts, rôles (owner/admin/moderator/member).

Routes Express

Auth (/api/auth) : register, login (JWT), get user, allUsers.

Workspaces (/api/workspaces) : CRUD workspaces, gérer membres, rôles.

Channels (/api/workspaces/:id/channels) : CRUD canaux (public/privé), gérer membres de canal.

Messages (/api/channels/:channelId/messages) : envoi, édition, suppression, réactions, read-receipts, mentions @, pièces-jointes (Multer).

Direct Messages (/api/direct-messages) : envoi, réaction, édition, read-receipts, pièces-jointes.

Notifications (/api/notifications) et Search.

Socket.IO

Événements en temps réel pour : nouveaux messages, modifications, suppressions, réactions, mentions, gestion de canaux/workspaces, statuts utilisateur.

3. Frontend Web (supchat-frontend)
React + CSS Modules

Organisation par pages (src/pages) : Login, Register, Chat, SearchResults, WorkspaceSettings, ProfileSettings, About, etc.

Composants partagés : Navbar, NotificationHub, UserMenu, Sidebar, ChatWindow, MessageBubble, MessageInput.

Thématisation

4 thèmes (light, dark, midnight, solarized) via CSS variables en styles/themes.css.

Stockage du choix de thème dans localStorage, appliqué sur data-theme de <html>.

Services

axiosConfig.js pour la baseURL, header JWT, gestion des erreurs.

Deux autres clients Axios pour Emoji et Giphy (sans token).

Fonctionnalités clés

Auth + JWT, gestion du profil + avatar (upload multipart), changement de mot de passe.

Navigation privée (PrivateRoute), recherches, paramètres de workspace et de profil.

Chat temps réel, envoi/édition/suppression de messages, réactions, scroll auto, focus sur message.

4. Mobile (supchat-mobile)
Expo/React Native

Structure très similaire :

Context pour Channel et Chat (sélection du canal ou de l’utilisateur en DM).

Navigator Stack + Drawer + BottomTabs.

Composants repris du web :

ChatWindow, MessageBubble, MessageInput, EditMessageModal, NotificationHub, SidebarDrawer, UserList.

Écrans alignés sur les pages web :

Auth (Login, Register, Forgot/Reset), Chat public, Direct Message, Création de channel/workspace, Gestion membres, Paramètres utilisateur et workspace, About, SearchResults (placeholder).

Services

axiosConfig.ts pointant vers l’API, setupAxiosToken.ts pour le JWT stocké en AsyncStorage, socket.ts pour Socket.IO.

Fonctionnalités implémentées

Connexion, navigation multi-écrans, lecture et envoi de messages, édition, réactions emoji (avec toast + haptics), scroll, upload d’avatar, gestion de canaux/workspaces, statuts en ligne (via socket).

Ce qui marche déjà
Authentification, création et gestion de workspaces et channels.

Chat temps réel (échanges publics et privés), édition, suppression, réactions emoji.

Thématisation et upload d’avatar sur le web.

Navigation mobile et appels API basiques fonctionnels.

À venir / points à renforcer
Correction de quelques écrans ou composants mobiles (erreurs TS, comportements inattendus).

Tests fonctionnels sur mobile (upload avatar, chat DM, paramètres profil).

Implémenter read-receipts visibles en UI (coches, indicateurs).

Statuts “en ligne/occupé” plus poussés, notifications push/locale.

Gestion des mentions (#/ @) dans l’interface mobile.

Synchronisation des thèmes web ↔ mobile (si souhaité).

Optimisation des uploads (compression), flows OAuth externes, CI/CD."
